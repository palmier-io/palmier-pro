# Generation lifecycle

## Admission and ownership

`GenerationService` owns submission, monitoring, and download tasks. `generate` and `enhanceDraft` throw before importing placeholders when their caller is canceled, generation is suspended, or the project package is closing/closed. Enhancement also validates the current library object and a nonempty source job ID before mutation. UI submissions preserve their input on refusal; Agent callers return a stable error instead of a placeholder ID. Audio placement checks admission before opening its editor transaction.

Stable initiation errors are `generation_project_unavailable`, `generation_suspended`, `generation_canceled`, `generation_invalid_draft`, and `generation_preparation_changed`. UI callers resolve separate `L10n` messages; these machine errors are not translated. Reference object/URL snapshots are checked before and after preparation. Timeline-scored audio checks its captured project/timeline after rendering and uploading, before creating or placing placeholders.

Suspension cancels and awaits every owned task, including tasks canceled before their body starts. Those tasks persist a failed cancellation state and invoke the initiating failure callback at most once. Suspension remains in effect after draining. `resumePendingGenerations` explicitly reopens admission only when the package is open and every suspension waiter has finished. A reopen during draining cannot restart work. Concurrent suspension callers cannot reopen admission prematurely.

## Acknowledged work

An acknowledgment's backend job ID is retained and checkpointed before cancellation is inspected. Reopen resumes monitoring of that same ID; it never repeats a submission or enhancement. Monitor IDs are deduplicated across fresh and restored tasks and released from task teardown, including pre-start cancellation. Missing configuration and interrupted streams produce observable failures while retaining recoverable IDs. They require a subsequent explicit lifecycle resume, not automatic paid retries or polling.

Backend updates must match their subscription ID and the current library object's job ID. Completion callbacks check current identity and cancellation after media finalization. Reference/preprocessing cleanup runs off-main on success, failure, and cancellation; returned original reference URLs are not treated as temporary files. Cleanup failures remain errors, including failures during cancellation.

Successful sibling outputs remain available when another output fails or cancellation interrupts a multi-output download. No refund, remote-job cancellation, or all-or-nothing provider output is implied.

Two outer boundaries are not a complete production coordinator: timeline scoring before `GenerationService.generate` remains work owned by its invoking UI/Agent task, and `ImageConverter.convertToJPEG` still suppresses deletion failure if conversion throws before returning its temporary URL. This slice surfaces cleanup failures for returned conversion files and scoring render files, but cannot observe an unreturned conversion URL. The preprocessing helper and UI preparation-task ownership remain outside this assigned slice; they require separate lifecycle verification/fixes before claiming complete cleanup or close/quit ownership.

## Download admission and Save As

A download attempt reserves the asset ID and snapshots the backend job ID, output index, logical source, status, import input, and generation presence. Package-local sources are stored relative to the package; their actual URL is resolved only after mutation admission. Native Save As can therefore rebase a queued placeholder without invalidating its download. External sources keep their exact URL. Admission validates the current library object, attempt, job, output index, parent context, and resolved source before publishing downloading state. It deliberately does not compare the reserved absolute URL or source revision across a legitimate pre-admission package relocation. After admission, the exact `PreparationContext` is authoritative, including source revision; status/import changes and URL changed away and back are superseding state, not another legitimate rebase.

The downloader returns an immutable `DownloadedMedia` value containing the temporary file URL and HTTP status. Production uses `URLSession`; tests inject local stages without network or paid provider calls. Installation, owned-stage cleanup, and rollback reuse `commitStagedProjectMedia` under the admitted package lease. Cancellation after a downloader returns but before installer handoff cleans the returned stage off-main. Failures caught inside the admitted download body settle before releasing that lease, so a queued save snapshots terminal state. Cleanup failure remains an observable error rather than being replaced by a cancellation message.

Matching admission refusal, task cancellation, and synthetic `CancellationError` settle the asset as failed and retain its pending remote link. Saved generation metadata retains the backend ID, result URLs, and output index for monitoring-based recovery. A changed source, source revision, status, import input, job, output index, or library object is superseding state: service admission, installation validation, both catch paths, failure settlement, and completion callbacks reject the obsolete attempt rather than replacing the newer state. HTTP and media-finalization failures also retain the link for download-only retry. Once installation publishes a current asset, those installed bytes remain available after a later finalization failure, cancellation, or stale refusal.

Retry reserves its attempt synchronously before task launch and ignores a duplicate while that reservation is active. Task teardown releases only its own reservation. Pre-start cancellation performs its matching failure settlement; once download execution starts, execution owns settlement, preventing duplicate checkpoints or a teardown cancellation from replacing a cleanup error. Successful finalization clears the pending link, publishes ready state (`.none`, persisted as no generation status), and checkpoints it. None of these paths resubmit paid generation.

## Media finalization

`MediaAsset.PreparationContext` snapshots source URL and source revision, generation presence/job/output, generation status, and import input. The source revision rejects a URL changed away and back. Identity measurement has a separate, matching attempt token, so overlapping identity work cannot publish an older measurement or invalidate the source snapshot merely by starting. `finalizeImportedAsset` adds current library-object and open-package checks to this context and passes that same owner hook into metadata and identity preparation.

Metadata preparation returns immutable, Sendable `MediaAssetMetadata` from URL/type/thumbnail-budget inputs. `loadMetadata`, library/preview thumbnails, and imported-media finalization share this loader and the same metadata publication operation. The existing four-permit metadata gate remains authoritative; acquisition and release are matched on success, error, stale completion, and cancellation. Context is checked after gate acquisition, loader completion, and permit release, then again at each caller before publishing duration, dimensions, FPS, audio presence, or thumbnails. Thumbnail callers also validate the context captured before waiting for their thumbnail permit.

Finalization revalidates after metadata preparation, unreadable-file existence checks, and identity measurement, including error paths. The identity operation checks context and library ownership before publishing a digest or verified flag; finalization checks again before status, manifest, offline/missing caches, or preview updates. Stale or canceled work returns false without writing a later failure or ready state onto newer work. Metadata legitimately published while the original context was still current is not rolled back if the context changes during subsequent identity preparation. Synthetic cancellation is distinct from unreadable media and does not publish a spurious read failure.

Image decoding and synchronous AVFoundation construction/setup execute inside explicit `@concurrent` helpers. AV assets, tracks, and image generators stay on that background executor; only scalar metadata and immutable CGImages cross to the main actor. AV properties use asynchronous loading. Video track duration remains preferred over asset duration, transformed dimensions retain truncation toward zero, valid positive nominal FPS and audio-track presence retain their existing meaning, and thumbnail images retain native pixel geometry. Non-finite/out-of-range dimensions are rejected before integer conversion; invalid media times are not published. Image duration remains the default still duration. Audio readability still requires an audio track, without changing the existing audio-asset `hasAudio` flag semantics.

This closes the identified AV setup and stale-finalization source paths in implementation, not yet in executed integration evidence. Lottie remains a separate limitation: the existing AppKit `LottieVideoGenerator.inspect` is main-actor isolated and still performs its own synchronous resource/view work. The new loader wraps its result as Sendable but does not move AppKit rendering off-main or repair that inspector's I/O. No claim is made that every media format is now entirely off-main, that responsiveness has been measured, or that provider integration/idempotency is complete.

`GenerationService.performDownload` carries the admitted context through download and installer validation, replacing it only inside its own installation publication. Shared finalization accepts an optional `onTerminalPublication` callback, emitted synchronously after the helper publishes its own terminal metadata/status/manifest state. The callback supplies that exact resulting context. It is not emitted for stale refusal or cancellation. The service accepts a changed finalization context only through this explicit receipt; neither a false Boolean nor equality with a failure label proves publication ownership. Newer failures with identical read/identity labels remain protected.

After the shared helper returns, the service revalidates object, attempt, job/output, and the expected context. A stale refusal returns false without calling failure settlement, changing the pending link, invoking completion, or checkpointing newer state. A refusal with a still-current context and no publication receipt settles as cancellation, including synthetic cancellation without a canceled task; there is no generic read-failure fallback. Owned read/identity failures retain the remote retry link and their helper-authored diagnosis. Owned success clears the link and invokes completion. A terminal publication that already won is not rewritten as cancellation merely because cancellation arrives afterward. All admitted terminal settlement and its once-only checkpoint complete before releasing the package lease, allowing a queued save to read the final state. Pre-start retry teardown continues to settle only an execution that never started.

## Blocker: lost backend acknowledgment

`generations:submit` returns a backend job ID only after its mutation returns. `generations:enhanceDraft` has the same acknowledgment boundary. Their current client contracts accept no persistent client request ID or idempotency key and expose no lookup by such a key. A connection failure or cancellation after backend acceptance but before the response arrives therefore leaves the client unable to distinguish rejected work from accepted, potentially charged work.

This implementation does **not** retry that submission, infer success from a matching prompt/project activity entry, fabricate a job ID, claim a refund, or treat the missing acknowledgment as proof that nothing was charged. The local placeholder reports failure with no backend ID. Reopening cannot safely recover or replay it. The same limitation applies to process termination before an acknowledged ID is durably saved.

The backend owner must provide an idempotent submit/enhance contract plus lookup by a durably recorded client request ID before automatic reconciliation is supportable. Until then, inspect the account's generation activity and billing with the provider/support before explicitly authorizing another paid attempt. This is an unresolved production-lifecycle gate, not a completed recovery feature.

### Manual checks

Use an isolated disposable project, never an existing user project:

1. With generation suspended or closing, submit from the generation panel, draft-enhancement menus, and Agent. Expect a localized refusal or stable machine error, preserved panel input, no new library item/placement, and unchanged undo history.
2. Cancel close after admitted generation starts. Expect exactly one failure settlement for the canceled local wait, an intact acknowledged job ID, and monitoring of that ID after reopen. Verify Save As, close, and quit with an active download; no late media installation may escape the coordinator.
3. Queue Retry Download behind Save As. Expect media installed only in the new package, ready library state, and matching saved bytes/manifest after save. Cancel before preprocessing/submission begins and during download; expect terminal matching placeholder state, a retained retry link for failed downloads, and no extra undo step. Retry Download must not repeat paid generation. Inspect temporary cleanup and completed sibling outputs. Retarget the source/job/output while waiting; expect the newer state untouched.
4. Verify keyboard/Return submission, Escape/dismissal, focus, disabled/empty states, replacement placement, and native undo. Check cancellation and interrupted-monitor messages in another locale after catalog integration.
5. Provider acceptance followed by a lost response requires external billing/job reconciliation. Do not repeat a paid request as a test without explicit spending approval.
6. In a disposable project, retarget generation job/output, import source, or status while metadata/identity preparation is active; cancel or remove/reinsert the item. Expect no late metadata, thumbnail, ready/failure status, or manifest write after the context changes. With unchanged media, verify still duration, rotated video geometry/FPS/audio presence, thumbnail proportions, normal import ready state, and save/reopen. Profile AV preparation with Instruments before claiming responsiveness gains; Lottie remains outside that claim.

`ToolExecutor+Speech` currently uses the speech/narration service rather than `GenerationService`; `ToolExecutor+Plan` delegates narration through its owning plan operations. Neither requires a generation API propagation patch in this slice, and both remain untouched for the active narration worker.
